# Бесшовное восстановление веб-сессии

Дата: 2026-08-18

## Контекст

При истёкшем access-cookie серверный layout получает `401`, видит безопасный httpOnly refresh-cookie и возвращает клиентский `SessionRefresh`. Сейчас этот компонент полностью заменяет рабочее пространство карточкой с текстом «Восстанавливаем сессию…». Из-за этого редкий технический переход выглядит как отдельный экран и создаёт ощущение перезагрузки приложения.

## Цель

Восстанавливать сессию без отдельного текстового экрана и без раскрытия личных данных до подтверждения авторизации. Пользователь должен видеть стабильный каркас платформы и, только если запрос заметно задержался, тонкую синюю полосу прогресса сверху.

## Не входит в задачу

- изменение backend-контракта `/web/v1/auth/refresh`;
- хранение или показ предыдущего приватного интерфейса из localStorage;
- изменение обычной загрузки страниц и переходов между разделами;
- изменение production-аутентификации или формата cookies;
- автоматические бесконечные повторы refresh-запроса.

## Пользовательское поведение

### Быстрое восстановление

1. Сервер возвращает безопасный нейтральный каркас рабочего пространства.
2. Браузер один раз вызывает `/web/v1/auth/refresh`.
3. Если ответ получен быстрее 150 мс, индикатор не появляется.
4. После `200` вызывается `router.refresh()`, и серверный layout подставляет подтверждённый профиль, баланс, чаты и текущую страницу без полной перезагрузки браузера.

### Медленное восстановление

1. Через 150 мс сверху появляется фиксированная синяя полоса высотой 3 px.
2. Полоса работает в неопределённом режиме: движется, но не показывает выдуманный процент.
3. Каркас страницы не прыгает и не меняет размеры.
4. После успешного ответа полоса исчезает вместе с заменой нейтрального каркаса на рабочее пространство.

### Недействительная сессия

Ответы `400`, `401` и `403` означают, что восстановление невозможно. Пользователь переводится на `/login`. Приватные данные до этого не отображаются.

### Временная ошибка

Сетевой сбой, таймаут 8 секунд, `408`, `429` или ответ `5xx` не должны разлогинивать пользователя. Каркас остаётся на месте, полоса останавливается, появляется компактное сообщение «Не удалось восстановить соединение» и кнопка «Повторить».

Нажатие «Повторить» запускает ровно одну новую попытку. Во время попытки кнопка блокируется, а отложенная полоса снова работает по тем же правилам.

## Компоненты

### `SessionRefresh`

Остаётся единственной точкой выполнения refresh-запроса и хранит минимальную фазу интерфейса:

- `pending` — запрос выполняется, визуальный индикатор ещё может быть скрыт;
- `slow` — запрос выполняется дольше 150 мс, полоса видима;
- `retryable_error` — временная ошибка, доступна ручная повторная попытка.

Компонент не принимает профиль, account ID, баланс или список чатов.

### `SessionRestorationShell`

Новый независимый презентационный компонент повторяет геометрию рабочего пространства:

- фон приложения;
- место шапки;
- место боковой панели на desktop;
- нейтральные скелетоны вместо аккаунта, баланса и чатов;
- основная пустая область;
- компактное состояние повторной попытки при временной ошибке.

Компонент не импортирует приватные данные и не пытается угадать их значения. На мобильном экране остаются только безопасная шапка, фон и основная область без выезжающего меню.

### `SessionProgressBar`

Независимый визуальный компонент:

- закреплён у верхней границы viewport;
- не влияет на layout;
- использует основной синий цвет дизайн-системы;
- имеет `role="progressbar"` и доступное имя;
- учитывает `prefers-reduced-motion`, заменяя бегущую анимацию спокойным пульсированием.

## Безопасность

- До успешного server refresh не показываются профиль, email, баланс, названия чатов или содержимое текущего диалога.
- Refresh-cookie остаётся httpOnly и не передаётся React-компонентам.
- CSRF-cookie читается только существующим browser API, а запрос продолжает отправлять `X-CSRF-Token`.
- Один mount создаёт только одну попытку; повтор возможен исключительно после явного нажатия пользователя.
- Неуспешный временный запрос не очищает cookies и не имитирует выход из аккаунта.
- Нейтральный каркас одинаков для всех аккаунтов и безопасен для серверного рендера.

## Производительность

- Нет дополнительных API-запросов кроме уже существующего refresh.
- Индикатор появляется с задержкой, поэтому быстрые восстановления не вызывают мерцание.
- Анимация использует только `transform`, не запускает layout и не зависит от JavaScript-кадров.
- Компоненты не читают localStorage и не кэшируют приватное состояние между аккаунтами.

## Доступность

- Визуальный текст «Восстанавливаем сессию» удаляется, но процесс имеет скрытое доступное имя.
- Состояние временной ошибки объявляется через `aria-live="polite"`.
- Кнопка «Повторить» доступна с клавиатуры и имеет заметный focus state.
- При `prefers-reduced-motion` исключается быстрое непрерывное движение.

## Тестирование

### Поведение запроса

- компонент выполняет один refresh-запрос;
- `200` вызывает только `router.refresh()`;
- `400`, `401` и `403` вызывают `router.replace("/login")`;
- сеть, таймаут, `408`, `429` и `5xx` показывают повтор, не вызывая переход на login;
- повтор создаёт ровно один новый запрос;
- rerender не создаёт дополнительный запрос.

### Интерфейс

- текст «Восстанавливаем сессию» отсутствует в видимой разметке;
- до 150 мс полоса скрыта;
- после 150 мс полоса видима и имеет `role="progressbar"`;
- нейтральный каркас не содержит приватных children, email, баланс или названия чатов;
- временная ошибка показывает сообщение и кнопку;
- desktop и mobile геометрия проверяются отдельными стилевыми контрактами.

### Регрессия layout

- `unauthenticated` по-прежнему переводит на `/login`;
- `refresh_required` возвращает только безопасный restoration shell;
- `unavailable` сохраняет текущее нейтральное состояние недоступности;
- `authenticated` без изменений возвращает существующий `WorkspaceFrame`.

## Критерии готовности

- при обычном быстром refresh пользователь не видит промежуточного сообщения;
- при медленном refresh видна только профессиональная верхняя полоса и безопасный каркас;
- временный сбой не разлогинивает пользователя;
- недействительная сессия безопасно переводит на login;
- существующие сценарии `/app` и все тесты платформы проходят;
- backend и production-схема cookies не изменены.
