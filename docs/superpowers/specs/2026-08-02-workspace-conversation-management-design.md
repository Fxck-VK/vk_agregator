# Управление чатами в рабочем пространстве

## Цель

Сделать список чатов в рабочем пространстве полноценным: пользователь видит активный чат, создаёт новый, переименовывает и удаляет чат, а интерфейс корректно ведёт себя на desktop и mobile.

## Границы

- Работают только чаты источника `web` и только для точного владельца-аккаунта.
- Создание остаётся существующим `POST /web/v1/conversations` с UUID idempotency key.
- Переименование добавляется как `PATCH /web/v1/conversations/{conversationID}` с телом `{ "title": string }`.
- «Удаление» в UI означает архивирование, а не hard delete: `DELETE /web/v1/conversations/{conversationID}` переводит собственный активный web-чат в `archived` и возвращает `204`.
- Архивированный чат не возвращается в списке, не принимает новые сообщения и не удаляет исторические сообщения, jobs и audit-данные.
- Повторное удаление собственного архивированного чата успешно и идемпотентно; чужой, не-web или отсутствующий чат всегда получает `404`.
- Production API, VK/Mini App чаты, платежи и модели не меняются.

## Серверный контракт

Все небезопасные методы проходят существующие проверки authenticated web principal, Origin, cookie/header CSRF и не раскрывают существование чужого чата.

### PATCH title

- UUID conversation ID в пути;
- строгий JSON без неизвестных полей, ровно `title`;
- title обрезается по краям, не пустой, максимум 120 Unicode code points;
- найден только через account + source=web + active status;
- успешный ответ: `200` и безопасный conversation DTO;
- некорректный запрос: `400`; отсутствующий/чужой/архивный/иной source: `404`; инфраструктурная ошибка: `503`.

### DELETE archive

- UUID conversation ID в пути;
- точный account + source=web check;
- собственный active чат архивируется, ответ `204`;
- уже архивированный собственный web-чат тоже возвращает `204` (idempotent success);
- отсутствующий, чужой или иной source: `404`;
- инфраструктурная ошибка: `503`.

Репозиторий получает отдельные account-scoped методы для user title и archive. Список web-чатов возвращает только active rows. Автоматическое заполнение первого заголовка worker-ом остаётся отдельным методом и не перезаписывает пользовательское имя.

## Интерфейс

### Список чатов

`SidebarConversations` становится клиентской границей списка: он использует текущий pathname, чтобы отметить ссылку активного чата через `aria-current="page"` и CSS class. Серверный layout по-прежнему получает initial list ровно один раз; после мутации UI использует `router.refresh()` для честного списка без локальной теневой копии.

На пустом списке показывается существующее понятное пустое состояние и доступна кнопка «Новый чат». Создание использует существующий `NewConversationButton`, сохраняет idempotency и переводит пользователя в созданный чат.

### Действия строки

Каждая строка выделяется в независимый `ConversationRow` component folder с собственным TSX и CSS module:

- название — обычная ссылка на чат;
- кнопка меню открывает доступные действия для этой строки;
- rename открывает локальную форму с первоначальным заголовком, Enter сохраняет, Escape отменяет;
- сохранение и archive блокируют только соответствующую строку, показывают доступную ошибку и не теряют текст в форме;
- archive открывает inline подтверждение «Удалить чат?»; подтверждение запускает archive и переводит на `/app`, если удаляется открытый чат;
- внешний click, Escape и Cancel закрывают меню/диалог без мутации.

### Mobile

`Sidebar` продолжает владеть состоянием drawer, focus trap и breakpoint <48rem. Нормальный переход по ссылке чата закрывает drawer, как сейчас. Кнопки меню, rename и archive не являются chat links и поэтому не вызывают закрытие. После успешного удаления текущего чата mobile drawer не остаётся поверх стартового экрана.

## Доступность и устойчивость

- Все иконки имеют видимые/доступные labels.
- Меню и подтверждение доступны клавиатурой; Escape закрывает, focus не теряется.
- Не выполняются optimistic deletes: список обновляется только после успешного сервера.
- Ошибки запроса показаны внутри затронутой строки с `role="alert"`.
- Никакой API key или account id не попадает в URL, DOM или лог UI.
