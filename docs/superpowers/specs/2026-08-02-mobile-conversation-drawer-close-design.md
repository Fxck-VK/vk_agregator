# Закрытие мобильного drawer при выборе чата

## Цель

При выборе недавнего чата в мобильном drawer пользователь сразу переходит к диалогу, а меню закрывается и больше не перекрывает рабочую область.

## Подходы

1. Передавать обработчик в `SidebarConversations` через новый клиентский контракт — требует перестройки текущего server-slot интерфейса.
2. Поднять всё состояние drawer в `WorkspaceFrame` — создаёт лишнюю связанность между layout и навигацией.
3. **Выбранный подход:** `Sidebar` обрабатывает обычный переход по ссылке чата внутри уже существующего слота разговоров. Это сохраняет независимость `SidebarConversations`, не меняет API/данные и локализует состояние drawer там, где оно уже находится.

## Поведение

- Только при ширине меньше `48rem`, когда drawer открыт, обычный переход по ссылке вида `/app/chat/...` закрывает drawer.
- Затем штатный `Link` продолжает навигацию к выбранному диалогу.
- Не восстанавливаем фокус на hamburger: пользователь намеренно перешёл в рабочую область нового чата.
- Modified-click (Ctrl/Cmd/Shift/Alt) и неосновная кнопка мыши не закрывают drawer, поскольку открывают ссылку иначе.
- На desktop и для ссылок вне списка чатов поведение не меняется.

## Проверка

- Компонентный тест открывает narrow drawer, нажимает ссылку недавнего чата и проверяет `aria-hidden`, `inert` и закрытое состояние панели.
- Существующие тесты навигации, focus trap и десктопного сайдбара остаются зелёными.
