# Встроенная базовая иконка модели

## Проблема

Базовая заставка модели сначала загружается как PNG из `/public`. На защищённом DEV-контуре запрос изображения может завершиться раньше клиентской гидратации, а переход к SVG выполняется только обработчиком `onError`. До этого пользователь видит браузерный значок сломанного изображения.

## Рассмотренные варианты

1. Оставить PNG и менять proxy/cache. Это сохраняет ненужную сетевую зависимость для базовой иконки.
2. Встроить PNG как data URL. Это резко увеличит JavaScript-бандл из-за исходного файла размером более 500 КБ.
3. Рендерить существующую улыбающуюся SVG-иконку сразу, когда индивидуальная заставка не передана. Это выбранный вариант: базовый вид не зависит от сети, авторизации, кэша и гидратации.

## Дизайн

- `ModelIcon` при отсутствии `src` сразу возвращает встроенную улыбающуюся SVG-иконку.
- При наличии `src` компонент загружает индивидуальную заставку через `next/image`.
- Ошибка индивидуальной заставки переключает компонент на тот же встроенный SVG.
- Сохраняются текущие `className`, размеры, сетка и стили потребителей.
- Публичный PNG остаётся в проекте для совместимости, но больше не является обязательным для базового UI.

## Проверка

- Тест подтверждает отсутствие `<img>` и сетевого URL для базовой иконки.
- Тест подтверждает загрузку индивидуальной заставки.
- Тест подтверждает переход индивидуальной заставки на встроенный SVG после `error`.
- Выполняются тесты всех потребителей `ModelIcon`, lint, typecheck, build и packaging.
