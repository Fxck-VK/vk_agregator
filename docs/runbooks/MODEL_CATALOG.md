# Единый каталог моделей

## Владельцы данных

`internal/service/productcatalog.WorkspaceCatalog` собирает публичную выдачу из
существующего реестра, доступности маршрутов и серверного pricingcatalog.
`GET /web/v1/models` требует web-сессию и возвращает `Cache-Control: no-store`.
В DTO нет провайдерских URL, ключей, внутренних ID или отчётов допуска.

Одна запись содержит публичный ID, название, описание, основной тип, категории,
статус проверки и массив типизированных операций. Категории интерфейса отдельно
от назначения: `popular`, `images`, `text`, `video-audio`, `free`, `study-work`.
Операция содержит входные возможности и один из блоков text/image/video/audio.
Сейчас исполнение сайта поддерживает текст, изображения и видео; аудио не
публикуется как доступная операция без соответствующего runtime.

Публичные настройки описывают доступный путь сайта. Неизвестная возможность
остаётся `support: unknown`, `enabled: false`. Документированная способность
провайдера не включает загрузку файлов на сайте автоматически.
Для непроверенных видеорезультатов `fps` и `audio` равны `null`, а не нулю и
«без звука». Это сведения о выходе; они не включают новый параметр запроса.
Маршруты, требующие референсов или автоматического определения длительности, скрыты до
подключения подходящего серверного пути. Допуск модели описан отдельно в
[Model onboarding](../../docs/runbooks/MODEL_ONBOARDING.md).

## Фронтенд

`model-catalog-cache.ts` — единственный сетевой загрузчик. Одновременные обращения
делят один запрос, успешная выдача хранится в памяти 60 секунд. Ошибка и неверный
контракт не заменяются придуманным списком. Парсер проверяет уникальность ID,
категории, основной тип, значения по умолчанию и наличие цены для вариантов.

Хедер, текущий диалог, новый чат, полный каталог, главная, генератор изображений
и инструменты файлов используют эти данные. Старые image/chat/video loaders
сохранены как чистые проекции. Старые HTTP-маршруты остаются совместимыми для
прежних клиентов; функциональный UI сайта их не запрашивает.

Подборки содержат только ID. В меню максимум пять моделей на категорию;
выбор категории поднимает её блок вверх. Полный каталог показывает все подходящие
модели. Описания поступают с сервера; `descriptionMode` меняет только отображение.
Хедер открывает новый чат, селектор в диалоге меняет модель текущего диалога.

Параметры и цены берутся из выбранной операции: image `price_by_variant`
учитывает качество и соотношение сторон; video `variants` ограничивает сочетания
длительности, разрешения и пропорций. Неподдерживаемые сохранённые настройки
заменяются допустимыми. Расчёт и списание остаются на бэкенде; UI не разрешает
платную операцию сам по себе. Файловые инструменты фильтруют конкретные операции
с включённым приёмом изображения. Их кнопки исполнения пока отключены, поскольку
обработка файла на сайте ещё не подключена.

## Проверки и локальный preview

Из корня репозитория:

```powershell
go run ./scripts/models/check
go run ./scripts/models/preview -check
go test ./internal/service/productcatalog ./internal/adapter/inbound/websession ./internal/service/imagegeneration
```

`go run ./scripts/models/preview` обновляет JSON для локального UI из того же
backend builder. Это офлайн-сценарий с синтетической доступностью маршрутов,
без секретов и запросов к провайдерам. CI проверяет актуальность файла.
Preview включается только в development через `NEIROHUB_LOCAL_WORKSPACE_PREVIEW`.

Frontend suite проверяет один общий запрос, категории, отображение текста,
изображений и видео, значения по умолчанию, цены и отсутствие отдельных записей
моделей/цен в функциональных UI-модулях. Backend-тест
`TestEveryPreviewOptionResolvesWithoutCallingProviders` проверяет каждый
опубликованный вариант через существующий resolver.

## Что не является подтверждением провайдера

43 старые записи сохраняют `legacy-unverified`. Успешные офлайн-проверки каталога
не подтверждают формат файлов, фактические лимиты, качество или успешный платный
результат. По каждой записи составлена [матрица оставшихся проверок](model-onboarding/existing-models-2026-09-14.md).
Платные live-проверки требуют отдельного DEV-контура и лимита расходов согласно
разделу «Реальные проверки» в `docs/runbooks/MODEL_ONBOARDING.md`. Ни preview, ни CI не запускают их.
