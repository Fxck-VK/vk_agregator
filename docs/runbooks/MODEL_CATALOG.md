# Единый каталог моделей

## Владельцы данных

`internal/service/productcatalog.WorkspaceCatalog` собирает публичную выдачу из
существующего реестра, доступности маршрутов и серверного pricingcatalog.
`GET /web/v1/models` требует web-сессию и возвращает `Cache-Control: no-store`.
В DTO нет провайдерских URL, ключей, внутренних ID или отчётов допуска.

Одна запись содержит публичный ID, название, описание, основной тип, категории,
статус проверки и массив типизированных операций. Категории интерфейса отдельно
от назначения: `popular`, `images`, `text`, `video-audio`, `free`, `study-work`.
Операция содержит входные возможности и один из блоков text/image/video/audio.
Сейчас исполнение сайта поддерживает текст, изображения и видео; аудио не
публикуется как доступная операция без соответствующего runtime.

Публичные настройки описывают доступный путь сайта. Неизвестная возможность
остаётся `support: unknown`, `enabled: false`. Документированная способность
провайдера не включает загрузку файлов на сайте автоматически.
Для непроверенных видеорезультатов `fps` и `audio` равны `null`, а не нулю и
«без звука». Это сведения о выходе; они не включают новый параметр запроса.
Маршруты, требующие референсов или автоматического определения длительности, скрыты до
подключения подходящего серверного пути. Допуск модели описан отдельно в
[Model onboarding](../../docs/runbooks/MODEL_ONBOARDING.md).

## Возможности API и интерфейса

Каждая запись также содержит `capabilities` версии 1 с отдельными профилями
`api` и `application`. Неизвестные лимиты остаются `null`/`unknown`; это не
положительный результат допуска. Профиль приложения ограничен параметрами
данного Web API и оценёнными вариантами. Загрузка референсов и переключатель
звука на сайте пока не подключены. В Mini App используется собственная проекция.

Оба профиля проходят строгий парсер и сохраняются во всех проекциях общего
каталога. Общий `ModelSelector` показывает их внутри раскрытого списка.
Полный инвентарь: [возможности моделей](../../docs/MODEL_CAPABILITIES.md).

## Фронтенд

`model-catalog-cache.ts` — единственный сетевой загрузчик. Одновременные обращения
делят один запрос, успешная выдача хранится в памяти 60 секунд. Ошибка и неверный
контракт не заменяются придуманным списком. Парсер проверяет уникальность ID,
категории, основной тип, значения по умолчанию и наличие цены для вариантов.

Хедер, текущий диалог, новый чат, полный каталог, главная, генератор изображений
и инструменты файлов используют эти данные. Старые image/chat/video loaders
сохранены как чистые проекции. Старые HTTP-маршруты остаются совместимыми для
прежних клиентов; функциональный UI сайта их не запрашивает.

Подборки содержат только ID. В меню максимум пять моделей на категорию;
выбор категории поднимает её блок вверх. Полный каталог показывает все подходящие
модели. Описания поступают с сервера; `descriptionMode` меняет только отображение.
Хедер открывает новый чат, селектор в диалоге меняет модель текущего диалога.

Параметры и цены берутся из выбранной операции: image `price_by_variant`
учитывает качество и соотношение сторон; video `variants` ограничивает сочетания
длительности, разрешения и пропорций. Неподдерживаемые сохранённые настройки
заменяются допустимыми. Расчёт и списание остаются на бэкенде; UI не разрешает
платную операцию сам по себе. Файловые инструменты фильтруют конкретные операции
с включённым приёмом изображения. Их кнопки исполнения пока отключены, поскольку
обработка файла на сайте ещё не подключена.

## Проверки и локальный preview

Из корня репозитория:

```powershell
go run ./scripts/models/check
go run ./scripts/models/preview -check
go test ./internal/service/productcatalog ./internal/adapter/inbound/websession ./internal/service/imagegeneration
```

`go run ./scripts/models/preview` обновляет JSON для локального UI из того же
backend builder. Это офлайн-сценарий с синтетической доступностью маршрутов,
без секретов и запросов к провайдерам. CI проверяет актуальность файла.
Preview включается только в development через `NEIROHUB_LOCAL_WORKSPACE_PREVIEW`.

Frontend suite проверяет один общий запрос, категории, отображение текста,
изображений и видео, значения по умолчанию, цены и отсутствие отдельных записей
моделей/цен в функциональных UI-модулях. Backend-тест
`TestEveryPreviewOptionResolvesWithoutCallingProviders` проверяет каждый
опубликованный вариант через существующий resolver.

## Что не является подтверждением провайдера

43 старые записи сохраняют `legacy-unverified`. Успешные офлайн-проверки каталога
не подтверждают формат файлов, фактические лимиты, качество или успешный платный
результат. По каждой записи составлена [матрица оставшихся проверок](model-onboarding/existing-models-2026-09-14.md).
Платные live-проверки требуют отдельного DEV-контура и лимита расходов согласно
разделу «Реальные проверки» в `docs/runbooks/MODEL_ONBOARDING.md`. Ни preview, ни CI не запускают их.

## Музыка и кандидаты APIMart — 16 сентября 2026

Каталог авторизованного сайта включает семь кандидатов с
`verification: pending-verification`: HappyHorse 1.0/1.1, SkyReels V4 Fast/Std,
Suno V6/V6 Wild/V6 Mini. Все их операции имеют `enabled: false`; обычные
генераторы исключают их из списка доступных моделей. API-возможности описаны
отдельно от возможностей приложения. Неизвестные FPS, звук и выходные лимиты
не заменяются предполагаемыми значениями.

Для новых видеомоделей публичный путь Job пока подготовлен только для генерации
по тексту. Адаптеры также описывают документированные режимы с кадрами,
референсами и редактированием; их загрузка и выбор в приложении ещё не подключены
и не должны включаться вместе с первым допуском text-to-video.

`/app/music` группирует Suno по задачам: создание, обработка выбранного трека,
музыкальные инструменты и собственные голоса/персоны/модели. Сервер описывает
33 действующие операции; устаревший Vox не предлагается. У каждой операции свой
набор входов, цена и поддержка Max/форматов. Один результат может содержать
произвольное количество треков. Номер трека сохраняется из исходного ответа
и не меняется при фильтрации или сортировке.

Собственные персоны и обученные модели выбираются по ID завершённых заданий
владельца (`persona_job_id` / `custom_model_job_id` в корне запроса, взаимно
исключающие). Идентификаторы провайдера разрешает worker. Голос отображается
как результат создания: он не подставляется вместо персоны. Музыкальный результат
открывается после `succeeded`, когда общий жизненный цикл завершил модерацию
и списание; промежуточные `result_ready` и `delivering` продолжают опрос.

HTTP-путь: `POST /web/v1/music-jobs/prepare` с `X-Idempotency-Key`, затем
подтверждение `POST /web/v1/music-jobs/{id}/activate`. История и результаты:
`GET /web/v1/music-jobs`, `GET /web/v1/music-jobs/{id}` и `/result`.
`GET /web/v1/music-artifacts/{id}` отдаёт только разрешённые владельцу байты
и поддерживает Range. Все записи требуют сессию; POST дополнительно требует
CSRF. Цена фиксируется сервером при подготовке, резервируется при подтверждении,
а списывается общим механизмом после обработки результата.

`POST /web/v1/music-inputs` принимает сырые MP3/AAC/WAV; локальная политика —
до 25 MiB и 480 секунд, для upload-cover/upload-extend строго менее 480 секунд.
MIME сверяется с содержимым и ffprobe, видеопоток запрещён. Это ограничение
приложения, а не утверждение о неизвестном лимите провайдера. Загрузка хранится
приватно; в Job передаются ID артефактов, а подписанные URL формируются worker.
Операции остаются закрыты до допуска, даже если инфраструктура загрузки настроена.

Цены кандидатов проверены по публичному APIMart pricing API 2026-09-16:
расчёт учитывает опубликованные Our price (скидку 20%), наценку ×3 и округление
вверх до 5 внутренних кредитов. Например, генерация Suno — 30, Max — 60;
обучение своей модели — 580. Это предварительные серверные котировки, не активные
строки runtime pricing. После подтверждённого допуска требуется опубликовать
точные pricing keys и настроить готовность провайдера; live-себестоимость ещё
не подтверждена.

Документированные ссылки и черновые контракты хранятся в
`providermodels/media_candidate_contracts.go`, текущие кандидаты — в
`providermodels/media_candidates.go`. Они не входят в `legacy.json` и не обходят
`Registry.ValidateOnboarding`. Для запуска нужны реальные проверки и допуск
по MODEL_ONBOARDING, активные bindings/тарифы и обычный DEV smoke. Реальные
проверки в этой доработке не запускались.

Перед выкаткой инфраструктуры применить additive migration
`000053_music_prepared_expiry`: она добавляет индексы истечения подтверждения
музыкальных заданий, не меняя пользовательские данные. API и worker используют
существующие `FFPROBE_PATH`, S3 и `PROVIDER_REFERENCE_BASE_URL` /
`PROVIDER_REFERENCE_SIGNING_KEY`; значения секретов здесь не фиксируются.
