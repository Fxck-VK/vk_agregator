# Локализация платформы

Подключены русский и английский. Страницы открываются под `/ru` и `/en`; язык URL всегда имеет приоритет над cookie. Переключатель находится в меню аккаунта и на публичной странице; в гостевой боковой панели и на странице входа его нет. Cookie `neirohub-locale` запоминает предпочтение для адресов без языка. Подробный контракт: [языковые адреса](locale-routing.md).

## Общая система словарей

В браузерных тестах название бренда берётся из общего `branding/brand.json`,
а не прописывается вручную. Например, `e2e/local-development.spec.ts` импортирует
JSON с `with { type: "json" }` для Node ESM и проверяет `${brand.name} печатает`:
ожидание следует переименованию бренда без отдельной правки тестов.

Все настройки бренда находятся в `branding/brand.json`: `name` — имя,
`logoPath` — основной логотип, `icons` — обычные, shortcut и Apple-иконки
с размерами и MIME-типом. Файлы размещаются в `public/assets/brand`, а выбранные пути
меняются только в JSON-конфигурации. `src/config/brand.ts` экспортирует значения
как `brandName`, `brandLogoPath`, `brandIcons` для существующих компонентов.
Go-пакет `web/platform/branding` включает тот же JSON в бинарник через go:embed:
имя используется в письмах с кодом и уведомлениях безопасности без чтения файлов
при отправке. Для сервера после изменения нужна пересборка API; для опубликованного
сайта — пересборка фронтенда. `BrandLogo` выводит изображение без обрезки и отдельной
фоновой заливки в Sidebar, PublicHeader, PublicFooter и подвале WorkspaceLanding;
размер задаёт место использования. `assetPaths.images.models.brand` ссылается на тот
же `brandLogoPath` для фирменного чата. Root layout берёт иконки из `brandIcons`.
Проверка `app/layout.test.tsx` сверяет выбранные PNG с объявленными размерами;
интеграционная проверка подставляет другие настройки для всех перечисленных мест.

Префикс скачиваемых примеров `brandFilePrefix` автоматически вычисляется из `brandName`
в `src/config/brand.ts`: нижний регистр, Unicode-нормализация, группы пробелов и пунктуации
заменяются дефисом, крайние дефисы убираются. Кириллица и другие буквы сохраняются;
если букв и цифр не осталось, используется `download`. Отдельно менять префикс не нужно.
Фото и видеопримеры используют `<brandFilePrefix>-<example.id>.png/mp4` в обоих языках;
пути исходных ресурсов и уже скачанные файлы не изменяются.

Название сайта задаётся один раз в `branding/brand.json`: `name`, экспортируемое как `brandName`. Основные и публичные словари обоих языков, формы входа, FAQ, приглашения, подписи главной, редакционные материалы и SEO используют это значение; монограмма вычисляется из него. После сохранения локальный dev-сервер обновляет интерфейс. Для собранного сайта нужна новая сборка. Встроенный `chatgpt` отображается как `<brandName> Chat`, если сервер вернул прежнюю фирменную подпись; идентификаторы, цены и названия внешних моделей сохраняются. Домен, адреса поддержки, cookies, ключи хранения, пути ресурсов и постоянные URL материалов от названия не зависят. Содержимое пользовательских сообщений и файлов не переименовывается.

Видимое фирменное имя выводит `BrandName` из `src/components/brand/BrandName/BrandName.tsx`; `monogram` выводит вычисленную монограмму тем же шрифтом. `BrandText` оформляет только отдельные вхождения имени в строках интерфейса (формы входа, приглашения, FAQ, подписи моделей), сохраняя полный текст и React-экранирование. Не применять его к переписке, промптам или именам файлов. В `branding/brand.json` реестр `wordmarks` сопоставляет ключ из текущего имени бренда с SVG-надписью и её размерами. Для Epifera знак и надпись извлечены из присланного владельцем SVG с сохранением контуров и градиентной точки над i; буквы наследуют цвет темы, размер масштабируется в em, начертание задано контурами. `BrandName` сохраняет обычное имя скрытым текстом для доступности, SVG декоративный. Новое имя без соответствующего SVG автоматически использует обычный текст Geist; монограмма и нативные placeholder тоже остаются текстом. Экспериментальный IBM Plex Sans сохранён с OFL-лицензией в `public/assets/fonts/ibm-plex-sans`, но не подключён и не загружается. У нативного placeholder невозможно оформить одно слово: `ChatTextInput` использует тот же шрифт для всей подсказки через общий `brandPlaceholderClassName`; введённый текст сохраняет обычный шрифт. В metadata, aria-подписях и строковых API остаётся обычный текст из словарей.

Все переводы расположены в `src/i18n` и используют один выбранный язык:

- `ru.ts` / `en.ts` — основные разделы: navigation, conversations, files, modelsCatalog, account, profile и другие.
- `messages/ru.ts` / `messages/en.ts` — дополнительные сообщения с ключами `component.message` и параметрами.
- `music.ts`, `music-catalog.ts`, `speech.ts` — сообщения музыки и речи, подключённые к общим каталогам. Смена языка обновляет подписи и ошибки без повторной загрузки каталога, сброса черновика или нового запуска задания.
- `public/` — существующие словари публичных страниц, подключённые к тому же языку запроса.
- `format.ts`, `counts.ts` — даты, числа, валюта и формы количества.
- `catalog.ts` — локализованные редакционные данные и совместимость с текущим серверным каталогом.

Компоненты используют `useDictionary()`, `useMessages()`, `useLocale()` из `LocaleProvider.tsx`. Серверные страницы — `getRequestLocale()` / `getRequestDictionary()`. Чистые функции получают язык, словарь или переводчик аргументом. Прямой импорт `ru` в компонентах запрещён.

Переносите целое предложение, включая пунктуацию, в словарь. Для новых параметров выбирайте смысловые имена: `{modelName}`, `{count}`, `{price}`. Для ссылок и выделений используйте `RichMessage` с именованными React-слотами: переводчик сможет менять порядок слов. React экранирует значения; HTML из словаря не исполняется.

## Загрузка и сохранение состояния

Root layout читает проверенный proxy заголовок языка из URL и сразу задаёт `lang`, `dir`, metadata и `RouteLocaleProvider`. На клиенте провайдер следует адресу, включая историю браузера. Server Action `setLocalePreference` запоминает предпочтение, затем `LanguageSwitcher` открывает ту же страницу на другом языке. Внутреннее дерево страниц сохраняется: черновики, модель, вложения и blob-превью не теряются. Изменяемого глобального языка нет, запросы и браузерные сессии независимы. Неизвестный язык в URL возвращает 404.

В состоянии храните коды ошибок и параметры, переводите при рендере. Для сообщений с параметрами есть `MessageReference` / `LocalizedError`. Не показывайте необработанный текст исключения провайдера. Ошибка каталога передаётся кодом `models_load_failed` и локализуется в компоненте выбора.

## Данные и форматы

Переписка, введённые промпты, имена файлов, названия пользовательских чатов и идентификаторы не переводятся. Редакционные примеры, FAQ и подписи создаются фабриками с текущим языком. Существующий `src/content` хранит редакционные переводы по языкам.

API описаний моделей поддерживает необязательное поле `description_translations: { ru, en }`, сохраняемое во всех проекциях каталога. Выбор: текущий язык → базовый русский → исходное описание. Общие описания и названия параметров старого API переводятся в адаптере отображения. Новое уникальное описание следует поставлять через `description_translations`; незнакомый внешний текст остаётся исходным. Кэш, операции, цены и параметры запросов от языка не зависят.

Используйте `formatNumber`, `formatDate`, `formatCurrency`, `countLabel` / `tokenAmount`. `Intl.PluralRules` выбирает `zero`, `one`, `two`, `few`, `many`, `other`; окончания задаёт словарь, включая контекст «за одну звезду». Даты файлов отображаются в UTC одинаково на сервере и в браузере. Цена остаётся в исходной валюте, пересчёта курса нет. Отформатированные подписи не должны становиться значениями API.

## Добавление языка

1. Добавить код и название в `locales.ts`, проверить направление в `getLocaleDirection`.
2. Создать полный основной словарь, дополнительные сообщения и публичный словарь с одинаковыми ключами, параметрами и стабильными `id`.
3. Зарегистрировать язык в `dictionary.ts`, `messages.ts`, `public/get-public-dictionary.ts` и `public/LocalizedPublicShell.tsx`. Типы требуют полноты реестров. Префикс URL и языковые альтернативы берутся из общего реестра `locales.ts`.
4. Заполнить формы количества, редакционные материалы и описания каталога. Перед выпуском проверить переводы человеком.
5. Запустить проверки и проверить реальные длинные фразы на мобильной и настольной ширине.

Для RTL подготовлены логические края боковой панели, направление клавиатурной навигации и рамки `ModeSwitchPanel`, нормализация `scrollLeft` в `ScrollArea`. Пользовательский текст использует `dir="auto"`, код — `ltr`. Арабский и другие языки пока не включены: подготовлена инфраструктура, а не их переводы.

## Проверки

- `npm run test:i18n`: ключи и параметры, формы количества, независимые запросы, сохранение формы, ошибки и проверка исходников.
- `npm test`: общий набор, включая i18n, и проверка ассетов; уже запускается в CI.
- `npm run typecheck`, `npm run lint`, `npm run build`, `npm run test:packaging`: типы, линтер, production-сборка и упаковка.
- `e2e/localization.spec.ts`: серверный язык, независимые сессии, переключение, перезагрузка, превью файлов, узкая ширина, длинные подписи и RTL.
- `e2e/locale-routing.spec.ts`: языковые URL, редиректы, история браузера, сохранение реального File/blob и модели, SEO, возврат после входа и оплаты с имитацией API.

Для браузерных тестов запустите dev-сервер с `NEIROHUB_LOCAL_WORKSPACE_PREVIEW=1`. Задайте эту же переменную тестовому процессу и `PLAYWRIGHT_BASE_URL=http://localhost:7159`, затем выполните `npx playwright test e2e/localization.spec.ts e2e/locale-routing.spec.ts --workers=1`. На Windows доступен `PLAYWRIGHT_CHANNEL=msedge`. Тесты используют локальные образцы, не запускают генерации и платежи.

Проверка исходников запрещает прямые импорты русского словаря, русские надписи вне каталогов, статичные JSX-подписи и фиксированную локаль `Intl`. Исключения ограничены словарями, редакционными данными, тестами, образцами переписки и явным списком брендов/форматов. Новый API-текст или сторонний виджет нужно отдельно включать в локализованный контракт.
