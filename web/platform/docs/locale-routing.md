# Языковые адреса платформы

Статус: действующий контракт с 2026-09-16. Заменяет прежнюю схему «русский без
префикса, английский под /en». Дизайн и состав публичных страниц не меняются.

## Источник языка и состояние

Все существующие страницы интерфейса имеют префикс `/ru` или `/en`, включая
главную, `/app/*` и `/login`. Язык адреса имеет приоритет над предпочтением.
`src/proxy.ts` перезаписывает `x-neirohub-page-locale` после проверки URL и через
`NextResponse.rewrite` направляет запрос на стабильный внутренний путь. Нельзя
доверять одноимённому заголовку клиента. Серверные словари читают этот заголовок.

Внутреннее дерево App Router общее для всех языков, поэтому смена языка не
перемонтирует диалог. `RouteLocaleProvider` следует видимому адресу, а
`LocaleProvider` предоставляет словари. Не добавлять `key={locale}` к диалогу или
его провайдерам. Черновики и File-объекты остаются в React; для переключения языка
они не сохраняются в localStorage или на сервере.

`LanguageSwitcher` валидированным Server Action сохраняет предпочтение и делает
переход на ту же страницу с другим префиксом. Query, hash и прокрутка сохраняются;
назад/вперёд возвращают соответствующий язык. Публичная оболочка также следует
контексту, поскольку серверные layouts сохраняются между переходами.

## Ссылки и совместимость

- Использовать `Link` из `@/i18n/Link`, а клиентские hooks навигации из
  `@/i18n/navigation`. Прямые импорты Next навигации вне i18n проверяются тестом.
- `push`, `replace`, `prefetch` добавляют текущий язык. `usePathname` возвращает
  внутренний путь без языка для сравнения активного раздела и состояния диалога.
- Чистые функции строят внутренний путь; навигация локализует его один раз.
  Серверный код может использовать `localizeHref(path, locale)`.
- API, callbacks, health, assets, Next resources, robots и sitemap имеют прежние
  технические адреса. `/en/web/v1/*` и подобные варианты возвращают 404.
- Старый адрес без языка получает 307 на предпочтение из cookie либо русский.
  Redirect имеет `Cache-Control: private, no-store`, чтобы preference не попадало
  в общий кэш. Неизвестные языки и отсутствующие страницы возвращают 404.
- Prefetch не меняет cookie языка и адреса возврата. `skipProxyUrlNormalize`
  сохраняет заголовки speculative-запроса для этой проверки.

## Вход и оплата

Адрес возврата после входа — только проверенный путь в `/app` с необязательным
языком. Короткоживущая HttpOnly cookie сохраняет только параметры `model`,
`quality`, `category`, `payment_id`, `pending`, `refresh` с ограниченными значениями.
Промпты, токены, произвольные query и внешние URL исключены. При входе используется
выбранный на странице логина язык. Secure/host-only контракт сессий не изменён.

Серверный возврат оплаты `/app/payment-return?payment_id=...` остаётся совместимым
через редирект. Ни браузер, ни локаль не определяют результат оплаты; серверная
проверка и идемпотентность прежние. Технические callback/API URL не локализуются.

## SEO и конфигурация

`WEB_ORIGIN` — доверенный server-only публичный origin без пути, query и credentials.
В production обязателен при обращении к публичным metadata/robots/sitemap.
Текущий DEV overlay передаёт существующий `WEB_ORIGIN` контейнеру platform.
В локальной разработке без настройки используется `http://localhost:7158`.
Canonical никогда не строится из клиентских Host/Forwarded заголовков.

`seo.ts` формирует self-canonical каждой версии и взаимные `hreflang`; `x-default`
ведёт на `/ru`. Сейчас существует только публичная главная, поэтому sitemap
включает только `/ru` и `/en`. Новые маршруты добавляются в реестр при реализации,
а не автоматически из заготовок контента. Кабинет и логин остаются noindex,
приватные данные защищены авторизацией. robots не является контролем доступа.

## Добавление языка и проверка

Добавить язык и полные словари по `localization.md`, включая типизированный реестр
`public/LocalizedPublicShell.tsx`. Routing использует общий `locales.ts`;
переписывать ссылки компонентов не требуется.

Проверки: `npm run test:i18n`, полная `npm test`, lint, typecheck, build и packaging.
`e2e/locale-routing.spec.ts` проверяет SSR URL против cookie, технические маршруты,
canonical/hreflang/sitemap, язык публичной оболочки, реальные File/blob-превью,
черновик и модель через переключение и историю, login и payment-return.
Браузерные проверки используют local preview; загрузка и авторизация имитируются,
платные генерации и реальные платежи не вызываются.
