# Добавление страниц: 24 общих шаблона

**Запись с данными → проверка → существующий компонент → адрес → публикация → sitemap.**
JSX, CSS и обработчики не копируются для новой статьи. Макеты сохраняются в `src/features/**` и общих компонентах. Старые и новые адреса используют один рендерер. Только русский сайт; `/en` остаётся перенаправлением.

## Создать страницу

Из корня репозитория:

```powershell
npm --prefix web/platform run content:list
npm --prefix web/platform run content:new -- T09 kak-sozdat-foto-tovara
npm --prefix web/platform run content:check
```

Создаётся `src/content/pages/entries/kak-sozdat-foto-tovara.json`. Команда печатает полный путь и адрес localhost. Это русская заготовка существующего примера с `draft/noindex`, которую нужно наполнить своим материалом. Существующий файл не перезаписывается.

1. Заполнить SEO-заголовок и описание в `seo`.
2. Изменить тексты, H1, изображения, примеры и ссылки в `content`.
3. Открыть напечатанный адрес на localhost:7159.
4. Выполнить `content:check` и исправить указанные поля.
5. После вычитки выставить `published/index`, фактические `reviewedAt`, `publishedAt`, `updatedAt`, например `2026-10-29T12:00:00Z`.
6. Проверить запись и выполнить обычный согласованный выпуск проекта. Локальное сохранение файла само по себе не выкладывает сайт на сервер.

Для следующей статьи создаётся следующий JSON. Изменение общего компонента или CSS обновляет оформление всех его записей.

## Поля записи

| Поле | Значение |
|---|---|
| `id` | Постоянный уникальный ID, латиница/цифры/одиночные дефисы |
| `template` | T01–T24 |
| `path` | Канонический адрес без `/ru`, query и fragment; латинский slug |
| `locale` | Только `ru` |
| `status` | `draft`, `review`, `published`, `archived` |
| `indexing` | `index` или `noindex` |
| `seo` | Обязательные `title` и `description` для выдачи |
| `publishedAt` | Начало публикации; будущая дата откладывает открытие новой страницы |
| `reviewedAt` | Фактическая редакционная проверка, обязательна для published |
| `updatedAt` | Содержательное обновление, передаётся в sitemap |
| `relatedIds` | ID связанных записей; существование проверяется. Видимые карточки и ссылки заполняются полями соответствующего макета |
| `content` | Полные именованные источники конкретного шаблона |

Вложенные источники не объединяются неявно. Неизменённый источник можно убрать целиком: будет использовано общее значение. У новой страницы обязательны её основной источник и данные собственной сущности. Заготовка уже содержит все источники.

SEO-заголовок и видимый H1 — отдельные поля. Редактируйте оба. Не меняйте опубликованный URL без перенаправления. ID моделей/фильтров, slug, пути и имена файлов не переводятся. Исторический суффикс `En` у источника не включает английский сайт: команда создаёт русские данные.

Единственный источник SEO страницы — верхний `seo`. Встречающееся внутри старых именованных словарей `metadata` сохраняет их структуру и не управляет SEO новой записи. Новые страницы добавляются в `content/pages/entries`; прежний трёхтипный граф `content/data` не является каталогом этих 24 публичных шаблонов.

## Медиа, ссылки, состав блоков

`src`/`poster`/`avatar` указывают существующий `/assets/...` в `public/assets`. `file` — имя файла в каталоге медиа соответствующего шаблона; проверка использует каталог исходного примера. В статье `imageIndex` должен существовать в массиве иллюстраций. Идентификаторы картинок и моделей сохраняются; реальные модели подключаются по отдельному onboarding-контракту.

Внутренние ссылки записываются без локали, например `/ai/image-generator`: локализатор добавляет `/ru`. Допускаются HTTPS/mailto. Связанные карточки, иллюстрации и другие парные массивы редактируются согласованно. Новый вид блока сначала добавляется в общий шаблон и его контракт, а не вставляется произвольным HTML.

## Публикация и проверки

Проверка включена в подготовку dev/test/typecheck/lint/build: известный тип/источник, обязательная структура полей и блоков, ID/адреса/slug, опасные ссылки, изображения, даты/статусы, связанные ID, группы справки, уроки, конфликты с маршрутами и служебными разделами.

Новые draft/review записи видны локально; production/DEV-сборка их не открывает. Действующие референсные страницы сохраняют прежнюю доступность/noindex до отдельной публикации. Archived страницы недоступны. Браузер получает источники только выбранной страницы.

Published/index страницы и их дочерние уроки/статьи автоматически попадают в `/sitemap.xml`. Черновики, архив, noindex и будущие публикации исключаются. Большая карта делится по 45 000 URL и размеру XML, корень становится индексом с `?part=N`. Проверен набор из 60 000 URL.

Адаптеры: `src/content/templates/render.tsx`. Привязки именованных данных — второй аргумент `usePublicCopy`. Существующие CSS и макеты не заменены. Источник пока файловый; серверное хранилище/CMS позже подключается через тот же контракт. Панель редактора и массовый импорт чужих материалов в эту работу не входят.
