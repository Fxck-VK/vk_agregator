# Общие состояния и порядок визуальной проверки

Задача: связать повторяющиеся состояния ожидания, ошибки и пустых данных в активном интерфейсе с общим оформлением. Это основа для последовательной доработки дизайна, а не утверждение, что все экраны уже визуально согласованы с пользователем.

## Где менять оформление

- [AsyncState.module.css](../src/components/ui/AsyncState/AsyncState.module.css) — круг прогресса, заглушка, сообщение состояния, область медиа и кнопка повтора.
- [globals.css](../src/app/globals.css) — `--state-placeholder-background`, `--state-notice-background`, `--state-border`, `--state-radius`, `--state-spin-duration`, `--state-pulse-duration`, `--state-shimmer-duration`. Цвета связаны с текущей темой.
- [MediaImage](../src/components/media/MediaImage/MediaImage.tsx) и [MediaVideo](../src/components/media/MediaVideo/MediaVideo.tsx) — готовность настоящего медиа, а не только ответа с метаданными.
- Геометрия страницы/карточки остаётся у потребителя. FileCard использует job.aspect_ratio/output_count, когда они известны; для старых заданий без размеров резервирует область 3:4; после получения размеров/загрузки остаются настоящие пропорции.

Один и тот же `RetryAction` использует утверждённый `RetryUploadIcon` и прозрачный Button. Контроллер определяет, что повторять; общий UI сам не создаёт Job, платёж или сообщение. MediaImage при повторе перемонтирует img с тем же разрешённым URL, MediaVideo вызывает load на прежнем video. Blob URL не создаются и не освобождаются общими медиакомпонентами.

Миниатюры внутри кнопок используют `passive`: в них нет вложенной кнопки повтора. Повтор доступен в большом просмотрщике. У FileCard кнопка открытия и повтор — соседние элементы. Upload progress и загрузка локального изображения — разные стадии; поверх одного вложения показывается один индикатор загрузки.

## Локальный просмотр

`/ru/app/ui-states` и `/en/app/ui-states` доступны только при `NODE_ENV=development` и `NEIROHUB_LOCAL_WORKSPACE_PREVIEW=1`; иначе сервер вызывает notFound. Ссылка также находится в панели с колбой. Здесь можно удерживать «Загрузку»/«Ошибку»/«Успех» на экране, видеть настоящие общие компоненты и открывать образец фото. Это визуальные образцы; они не запускают генерацию и оплату.

## Ожидание нескольких изображений — 20 сентября 2026

Согласованный вариант: количество заглушек равно количеству фото в отправленном
запросе; четыре фото образуют сетку 2×2. Формат каждой заглушки соответствует запросу,
по центру используется общий MediaState. Весь набор ждёт одну серверную задачу:
персональные проценты и частичная готовность не выдумываются.

- [x] Общий ImageGenerationGrid для ожидания и готовых фото; локальные примеры 1–15 фото.
- [x] Подключение к новому и существующему чату, включая этап отправки запроса.
- [x] Сохранение только количества и формата в записи ожидающей задачи; восстановление после обновления страницы.
- [x] Проверки смены ожидания на результаты/ошибку, RU/EN, двух тем, узкого экрана и reduced motion.

Точка просмотра: `/ru/app/ui-states#image-generation`. Переключатели вверху страницы
удерживают нужное состояние. Готовый результат в этом примере повторяет локальное
изображение, запросы к нейросетям не отправляются.

Проверка в настоящем чате: `/ru/app/chats?model=seedream_5_0_lite`.
В инпуте выбрать количество и формат, в колбе — «Отправка сообщения → Медленно».
Через восемь секунд общий ожидающий набор заменяется тем же количеством тестовых
изображений в выбранных пропорциях; каждое открывается в FilePreviewDialog.
Число результатов ограничивается каталогом выбранной модели (у Seedream 5.0 Lite — 15).
Тестовые фото повторяют один локальный образец, не зависят от текста запроса;
локальная история и ожидание удаляются при перезагрузке вкладки. Сохранение
ожидающей задачи после reload относится к настоящему backend, не к этому симулятору.

## Существующие и отдельно обсуждаемые элементы

- Сетевая плашка ChatUploadNetworkNotice, предупреждение о дубликате ChatAttachmentNotice, ReferenceQuoteNotice уже используют согласованные PopoverSurface/ModalBackdrop/Button/ModalCloseButton. Их расположение, фирменная иконка и анимация сохранены; они не заменены универсальной плашкой с другой геометрией.
- FilesEmptyState, AssistantTypingIndicator, SessionProgressBar и ModelIcon уже общие; они сохраняют свою роль. Для фото индикатор размещается в каждой заглушке; текст и видео сохраняют индикатор «нейросеть думает».
- Обычные описания профиля, неподключённых возможностей и ограничения модели остаются информативным текстом. Их наличие само по себе не ошибка оформления.
- Аудит содержал дополнительные функциональные пробелы, например отсутствие уведомления о сбое clipboard. Объединение состояний не добавляет новые продуктовые действия и не объявляет такие пробелы исправленными.
- Резервные компоненты без активных потребителей (ImageJobHistory, NewConversationButton, public EmptyState, запасной logout AccountMenu) в эту миграцию не включены.

Проверки: поведение общего прогресса, обработка error/load и смены src, повтор без открытия карточки, сохранение video ref; существующие тесты чатов, файлов, моделей, платежей и сессии; браузерные сценарии загрузки/ошибки/повтора, desktop/mobile, светлая/тёмная тема и reduced motion. Итоговые результаты запуска фиксируются в сообщении о выполнении.

Архитектура получения данных и проверенные сетевые сценарии: [preloading.md](preloading.md).
