# Русские публичные шаблоны

Все 24 типа публичных шаблонов работают на `/ru` и `/en` в одном проекте.
Английские slugs сохраняются: например, `/ru/ai/image-generator`.
Русские юридические документы остаются утверждённым исходным текстом;
повторный перевод их содержания не выполняется. Черновики сохраняют noindex:
перевод сам по себе не публикует страницу и не добавляет её в sitemap.

## Данные и компоненты

`src/i18n/public/*-en.ts` — исходные редакционные данные. Соответствие исходных
фраз стабильным ключам хранится в `translations/sources.json`, русский каталог —
в `translations/ru.json`. `localizePublicData(data, locale)` создаёт неизменяемую
проекцию данных; `usePublicCopy(data)` получает язык из существующего
LocaleProvider. Серверные metadata и фабрики получают язык явно через
getRequestLocale. Изменяемого глобального языка и подмены DOM нет.

ID, slugs, ссылки, пути ассетов, цены и технические перечисления не переводятся.
Теги материалов сохраняются как ID; `collection/tag-labels.ts` переводит подписи
для отображения и поиска. Редакционные теги курса переводятся как обычный текст.
Защищённое поле `value` может содержать и техническое значение, и текст:
доверенные подписи таблиц моделей/тарифов переводятся явно в компоненте.
Пользовательский ввод, имена файлов и приватные данные в этот механизм не передаются.

Для форматируемых фраз используйте `translatePublicMessage` с именованными
параметрами; число и валюту форматируйте существующими i18n-функциями.
Склонение количества материалов использует `countLabel` и основной словарь.
Однотипные элементы переиспользуют существующие компоненты; отдельной русской
копии вёрстки нет.

## Добавление и изменение текста

Общий каталог предназначен для шаблонов и их текущих редакционных примеров.
При массовом наполнении тысячи статей и карточек должны хранить локализованный
контент отдельными записями, загружаемыми для конкретной страницы (существующий
слой `src/content`), со своим аудитом перевода. Не добавляйте весь будущий каталог
материалов в общий клиентский словарь. Правила обратного перевода и проверки
фактов применяются и к таким записям.

1. Измените английские редакционные данные и запустите `npm run public-copy:check`
   из `web/platform`. Проверка покажет отсутствующую фразу и её место в данных.
2. В `docs/research/ru-template-translations/additional-<пакет>.json` добавьте
   записи `{source, ru, back}`. Сначала выполните EN → RU, затем отдельным проходом
   переведите RU обратно на английский, не подставляя исходник вместо результата.
3. Сравните исходный и обратный тексты: факты, числа, отрицания, ограничения,
   условия доступа, статусы planned/reference и авторство. Исправьте русский
   вариант при расхождении. Проверьте естественность фраз в их окружении.
   Бренды и технические обозначения можно оставить с объяснением `keepReason`.
4. Запустите `npm run public-copy:generate`. Команда добавляет новые стабильные
   ключи, не перенумеровывая старые, и собирает runtime-каталог без обратных текстов.
   Для существующего source исправляйте исходную запись аудита; дополнительная
   запись не переопределяет уже проверенный перевод молча.
5. Повторите `public-copy:check`, typecheck, lint и затронутые тесты. Проверьте
   русский и английский URL, metadata, поиск/фильтры и длинные строки на телефоне.

Сохранённые обратные переводы находятся в `docs/research/ru-template-translations/`:
g1/g2/g3 — первоначальные 3634 фразы; additional-* — подписи и форматируемые
сообщения, найденные при интеграции; count-forms — формы количества. Это отдельные
проходы перевода и смысловой сверки, выполненные агентами, а не заключение
независимого переводчика. Автоматические проверки подтверждают полноту записей,
параметры, числа, пробелы и соответствие каталога, но не заменяют вычитку.

`public-copy:check` входит в prebuild/pretypecheck/pretest/prelint. Проверка
источников читает только доверенные статические данные этого репозитория и
не обращается к внешним переводчикам или AI API.

Docker-сборка копирует аудит переводов в `/docs/research/ru-template-translations`
только в build-stage. Проверка находит исходники относительно пакета и работает
как в полном checkout, так и в плоском `/app`. В runtime-образ аудит не копируется.
`npm run test:public-copy` проверяет оба расположения и отказ при отсутствии аудита;
эта проверка входит в общий `npm test`.
