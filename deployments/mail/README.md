# Почта Epifera: работа над оформлением

Почтовый клиент — Roundcube. Наша тема `epifera` наследует рабочий интерфейс
`elastic`; в этом проекте хранятся только наши дополнения.

## Что редактировать

- `skins/epifera/styles/epifera.css` — цвета, размеры, отступы, состояния кнопок.
- `skins/epifera/templates/` — свои шаблоны. Не копируйте весь Elastic: добавляйте
  только изменяемые файлы, сохраняя Roundcube-объекты форм и обработчиков.
- `skins/epifera/meta.json` — описание темы и дополнительные ссылки.
- `roundcube.config.php` — публичные настройки клиента, без паролей.

Название, логотип и favicon берутся при сборке из общих
`web/platform/branding/brand.json` и `web/platform/public/`. Копию логотипа в этой
папке вручную создавать не надо. Маркер `__EPIFERA_UI_REVISION__` в ссылках
заменяется версией исходников, чтобы браузер обновлял стили после выкладки.

## Проверка и публикация

В Linux/WSL из корня репозитория:

```sh
python3 -m unittest discover -s scripts/mail -p 'test_*.py'
bash -n scripts/deploy/deploy-mail-ui.sh deployments/mail/renew-certificates.sh
```

Рабочая ветка публикации — `dev-deploy`. После пуша изменений темы или общих
ресурсов бренда запускается **Deploy Mail UI**. Workflow сначала проверяет
упаковку и откат, затем выкладывает точную версию на
<https://mail.epifera.com/>. Изменения только почты не запускают сборку образов
основного приложения. Для pull request выполняются только проверки.

Настоящие письма, пользователи, пароли, сертификаты, DKIM-ключи и SQLite
находятся на VPS. Не копируйте их в репозиторий. Для изменения CSS доступ
к содержимому ящика не требуется. На сервере перезапускается только веб-клиент;
SMTP/IMAP продолжают работать. При неудачном обновлении возвращается предыдущая
версия интерфейса, а workflow остаётся красным с причиной ошибки.

Настройка сервера, доступ и ручной откат:
[SUPPORT_MAIL.md](../../docs/runbooks/SUPPORT_MAIL.md).
